# 维护、状态和验证

以下是无既有规范时的默认规则；目标项目已有的状态命名、统计与维护约定优先。若这些规则与项目事实冲突，标明冲突，不静默改写历史。

## 默认状态和复选框

| 状态 | 复选框 | 含义 |
|---|---|---|
| 待开始 | `[ ]` | 尚未开始实施或验证。 |
| 进行中 | `[ ]` | 正在处理；并行工作可存在，应记录各工作项及负责人或上下文。 |
| 待验证 | `[ ]` | 实现已完成，但规定的验收或证据尚未全部完成。 |
| 阻塞 | `[ ]` | 有阻碍推进的条件，记录影响、解除条件及下一步。 |
| 已完成 | `[x]` | 实现、所有适用验收和证据齐全。 |
| 已取消 | `[ ]` | 决定不实施；保留编号、原因及决策依据。 |

开始工作时更新为进行中；实现完成但缺验收时转待验证；满足所有适用完成条件并留证后转已完成。直接完成纯文档或调查任务同样需要其相应的完成条件及证据，不强制伪造一次中间状态。发现完成项回归或证据失效时，保留历史，按实际情况重新打开并说明原因。若既有项目使用其他状态，依据其语义判断，不随意更名；默认复选框原则是完成验收才勾选。

## 汇总口径

- 默认有效总数 = 统计层级内所有任务数 − 已取消任务数；完成数只统计已完成任务。百分比 = 完成数 / 有效总数；有效总数为 0 时记为“不适用”，不写 100%。同时列出取消数量及原因入口。
- 分阶段及整体统计使用相同层级和口径，父子任务不重复计数。待验证、阻塞和取消均不算完成；百分比仅表示任务执行进度，不自动代表交付验收通过。
- 仓库已有统计方式优先，例如将取消项保留在总数中时，不擅自切换口径；明示口径及取消数量。进度汇总从唯一事实来源计算，不通过汇总表反向推断或重写任务状态。

## 证据和更新

- 每次进度更新尽可能记录日期、工作内容、任务编号、验证结果、未完成项、下一项和阻塞。日期未知时写未知，不把确认日期冒充测试日期。
- 自动化、静态分析、真实环境运行和用户手测分别标注来源、执行者、日期、环境、范围、结果与限制；已有历史证据可引用，但不能声称本次重新执行。用户确认仅覆盖其明确说到的范围。
- 记录通过、失败、部分通过、未执行和阻塞；跳过必须说明原因，不能计为通过。涉及可复现检查时记录实际命令和结果；没有证据时保持未完成或待验证。
- 生产数据、真实账号、迁移或破坏性操作需事先确认环境、影响、备份／回退及授权；测试应使用适当隔离的环境和数据。避免写入密钥、连接串、私人原文或未授权内容。
- 需求或范围改变时，先依目标项目决策流程确认、维护上游文档，再调整依赖、验收和受影响任务。只有在用户允许的修改范围内同步任务、进度、证据和索引；跨任务集共享证据时引用原记录，并维护各自权威状态，不重复制造验收结论。
