# 默认任务集模板

仅在目标仓库没有适用约定时采用；用户指定和仓库规则优先。按任务规模裁剪章节，保留任务事实来源、可检验的完成条件和验证证据。占位符不是已确认事实，填写实际信息，未知项写“待确认”或省略，不把示例内容当作项目事实。

## 目录和索引

```text
docs/tasks/
├── README.md
└── 01-任务集名称/
    ├── tasks.md
    ├── progress.md
    └── verification.md
```

为新任务集选择未占用的目录编号；已有目录不重命名。根索引列出任务集目标及其任务、进度、验证入口，说明状态事实来源及适用的维护规则。已有索引做增量更新，不覆盖其他任务集。

## `tasks.md`

````markdown
# <任务集名称> · 任务清单

最后更新：<日期>。本文件是任务状态的事实来源；[进度](progress.md) 汇总现状，[验证记录](verification.md) 保存证据。

## 目标与边界

- 目标：<要交付的结果>
- 本次不做：<明确排除的范围>
- 上游依据：<适用的需求、方案、计划、决策或用户确认；用有效链接>
- 现状及限制：<已核实的实现和证据范围；与假设、待验证内容区分>

## 阶段 A — <阶段名称>

- [ ] **<前缀>-A01 · <任务名称>**｜状态：待开始｜依赖：无
  - 完成条件：<可观察的结果和适用的成功／失败路径>。
  - 验证：<验证场景或验证记录中的编号；未执行时不要写成通过>。

- [ ] **<前缀>-A02 · <任务名称>**｜状态：待验证｜依赖：<前缀>-A01
  - 完成条件：<结果及未完成的验证>。
  - 验证：<指向 verification.md 的记录；未执行及限制>。

- [x] **<前缀>-A03 · <任务名称>**｜状态：已完成｜依赖：<前缀>-A01
  - 完成条件：<已满足的结果>。
  - 验证：<指向真实、完整验收证据的链接或编号>。

## 顺序与风险

- <依赖顺序、可并行条件、阻塞或安全边界>

## 待确认事项

- <会影响范围、设计或验收的未决问题>
````

以上三个任务仅用于说明不同状态；新建文档时只写真实任务，不将示例状态视为默认结果。任务项顶层才用于统计，说明、验收和子步骤不要再使用可被误计数的复选框；确需子任务时分配稳定编号，明确统计层级，避免父子重复计数。

## `verification.md`

````markdown
# <任务集名称> · 验证记录

最后更新：<日期>。本文件记录证据，不是任务状态的事实来源；任务状态见 [任务清单](tasks.md)。

## 验证矩阵

| 编号 | 对应任务 | 场景与预期 | 结果 | 证据及限制 |
|---|---|---|---|---|
| <验证编号> | <任务编号> | <可复现的场景及预期> | 未执行 | <环境、依赖或未覆盖范围> |

## 执行记录

- <验证编号>｜<日期>｜<执行者>｜<环境及非敏感版本>：<操作或命令>；预期 <预期>；结果 <通过／失败／部分通过／未执行／阻塞>；证据 <位置或用户确认范围>；限制及后续 <内容>。
````

根据项目需要追加专项报告或独立证据文件，并在验证记录中引用；敏感原始日志或截图不进入仓库。
