# 前端动效规范

动效应解释状态变化、反馈操作或引导注意力，不应延迟任务、掩盖状态或让界面显得忙碌。本 skill 适用于框架无关的 Web 前端；React、Vue、Svelte 等项目均优先遵循项目已有组件、样式和动画约定。

## 工作流程

1. 明确用户目标、触发条件、起始和结束状态、作用元素，以及效果是否持续或可中断。区分真正的运动效果与玻璃、颗粒等静态视觉质感。
2. 读取 `references/effect-catalog.md`，从词典中选择最贴近目标的效果；组合效果时说明每一层的用途，不要把词典当成需要一次用全的清单。若命中词典的 12 个经典效果之一，按词条链接只读取对应的 `references/effects/*.md` 模板。
3. 检查项目现有的设计 token、组件、动画库、输入方式和减少动态效果处理；沿用已有约定，不引入平行系统。
4. 需要代码参考时读取 `references/implementation-templates.md`，将模板适配项目结构、设计 token 和生命周期；不要不加检查地复制。
5. 选满足需求的最低复杂度实现方式，并明确窄屏、触屏、键盘、浏览器不支持和 `prefers-reduced-motion` 下的行为。
6. 验证正常播放、快速重复操作、中断或反向操作、内容加载和组件卸载；报告实际完成的验证，不声称验证未运行的场景。

## 选择与组合

- 先为动效确定一个职责：确认操作、显示状态、引导视线、表达层级或建立空间关系。若没有明确职责，省略动效。
- 一个页面通常只需要一个主要视觉效果，搭配少量辅助交互。限制同时运动的焦点；避免多个循环背景、发光按钮、视差和文字入场彼此争抢注意力。
- 可将鼠标效果用于桌面增强，但不能让 hover 成为发现或完成操作的唯一方式。触屏上关闭、简化或改为明确的点击交互；避免隐藏系统光标后没有可靠替代。
- 加载反馈应反映真实等待状态；庆祝效果留给有意义的完成事件；循环动画应低干扰、可停止，并在结束状态仍然明确。
- 视差、平滑滚动、自动轮播和全屏转场会改变用户对页面的控制感。优先保留原生滚动、导航历史、焦点和停止操作。

## 实现方式

- 简单、状态驱动的属性变化优先用 CSS `transition`；有限且自包含的片段优先用 CSS `@keyframes`。
- 需要脚本控制时间线、播放方向或逐帧协调时，可使用 Web Animations API。复杂手势、布局过渡或跨元素时间线优先评估项目已有动画库；确有必要时再引入依赖。
- 优先动画化 `transform` 和 `opacity`。谨慎动画化会触发布局、昂贵滤镜或大面积重绘的属性；`blur`、`backdrop-filter`、阴影、混合模式和大量粒子应在目标设备上验证成本。
- 不要在动画每一帧中更新框架状态或触发大范围重新渲染。动画应与业务状态分离，并在取消、重播、卸载时清理动画、监听器、计时器和帧循环。
- 不要默认使用 `will-change`；只有测量证实有益时才短暂应用。Canvas 动画应限制绘制面积和粒子数量，在无用户输入且无可见变化时暂停帧循环。
- 优先复用项目的时长、缓动和间距 token。若没有 token，微交互可从 150–300ms、卡片或面板过渡可从 300–600ms 试起；这些是设计起点而非硬性规定。背景循环应缓慢且克制，并可暂停。
- 使用 CSS、SVG、Canvas 或浏览器新 API 前，核对目标浏览器支持情况。对 `interpolate-size`、scroll-driven animations、View Transitions、滤镜和遮罩等能力提供静态或渐进增强回退；不支持时核心内容和交互仍须正常工作。

## 无障碍与验收

- 支持 `prefers-reduced-motion: reduce`：减少或移除非必要运动，同时保留状态变化、内容可达性和操作反馈。不能只把时长设为零而留下错误的中间状态。
- 不让信息、错误、成功、焦点或可操作状态只通过动画、颜色或空间位置传达。动画期间保持键盘焦点可见且顺序稳定；弹层关闭后按交互语义恢复焦点。
- 避免快速闪烁和可能诱发不适的全屏运动。持续且非必要的运动应允许暂停或停止；自动播放内容需提供相应控制。
- 验收：鼠标、键盘和触屏的主要路径都可用；快速重复、反向操作、取消和卸载不会留下错位状态或未清理任务；减少动态效果时内容完整可读；目标视口没有明显抖动、溢出或滚动卡顿。

## 动效提示词

用户需要提示词而非代码时，使用简洁、可执行的描述，至少写清：

1. 效果名称，以及它要解决的体验问题。
2. 作用元素与起始、结束状态。
3. 触发方式（悬停、点击、滚动、加载或状态改变）。
4. 关键参数（距离、时长、缓动、范围、延迟或粒子数量）；没有依据时给可调整的起点，不伪装成唯一正确值。
5. 手机、触屏、键盘、`prefers-reduced-motion` 和浏览器不支持时的降级行为。
6. 性能边界、停止条件以及需要验证的状态。

写实现前检查项目上下文。不要仅凭提示词就假定技术栈、浏览器支持、内容结构或允许添加依赖。
