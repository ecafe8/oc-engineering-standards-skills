# 任务、诊断与验证

## 任务契约

| 任务类型 | 期望行为 |
| --- | --- |
| 安装 | 使用已确认的锁文件和项目指定安装范围，不悄悄重新解析依赖 |
| 格式化 | 用户显式调用时可修改文件，明确作用范围 |
| 检查 | 格式、静态分析、类型和测试覆盖真实项目；失败以非零退出码传递 |
| 诊断 | 报告工具版本与必要的解释器身份，不打印秘密 |

任务名不证明行为：例如 Python 检查命令可能同步 `.venv` 或缓存，需检查实际选项；运行真实模型、数据库、网络或部署任务可能产生业务副作用，须按请求和授权处理。不要为项目中不存在的测试或类型检查宣称覆盖。

## 排查顺序

1. 确认目标目录、适用配置与 mise 版本，再检查工具是否安装和实际解析到的版本。
2. 检查任务调用的脚本、工作目录、shell、环境变量来源及嵌套配置。不要显示敏感值。
3. Python 问题额外核对 `UV_PYTHON`、uv 版本、虚拟环境的基础解释器和兼容范围；`uv-standards` 是可选补充。未安装时依据本 Skill 的配置参考、目标项目配置和 uv 官方文档继续排查。
4. 锁文件不一致时对照清单和 Git 差异；只有明确的更新任务才重新生成。不要用忽略一致性检查的方法伪造成功。
5. 报告本机平台及实际执行结果；CI、容器、其他架构没有执行时标为未验证。

## 验证清单

- 有针对性地运行目标项目现有任务；工具安装可能需要网络、信任或写入磁盘，先确认范围。
- 若要求源码和锁文件只读，运行前后比较相关文件或 Git 差异，同时如实说明缓存与环境写入。
- 新增任务要验证被委托命令存在、工作目录正确、错误能传递且没有意外调用外部服务。
- 不自动清理环境、缓存或覆盖配置来使检查通过。

参考：[mise 任务](https://mise.jdx.dev/tasks/)、[mise exec](https://mise.jdx.dev/cli/exec.html)。
