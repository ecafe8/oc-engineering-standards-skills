# 解释器、环境与排障

## 所有权

- 项目可能由 mise、uv 或其他机制提供 Python；先检查配置，不自动变更所有者。`requires-python` 表示支持范围，不是必须使用的精确补丁版本。
- workspace 默认共享根环境；若设置了自定义环境路径，按目标配置判断实际位置。uv 管理环境不要求用户手动激活。
- 若项目明确由 mise 提供 Python，可通过其支持的集成方式让 uv 使用该解释器；`mise-standards` 的配置参考是可选补充。未安装该 Skill 时，检查目标仓库的 mise 配置并按对应版本的官方文档验证集成。验证实际解释器及虚拟环境基础解释器，而非只看版本字符串。
- 修复已存在的错误环境时先确定路径和影响；若需删除或重建，仅在确认可再生且获授权后进行，不触碰不明目录。

## 故障排查

| 现象 | 先检查 | 处理方向 |
| --- | --- | --- |
| 锁定同步失败 | 根和成员清单、锁文件差异、uv 版本 | 有意变更才重新解析；不能用 `--frozen` 隐藏过期锁 |
| 成员不能导入 | 安装范围、发行名与导入名、构建后端、包发现 | 修正声明或安装，不通过 `PYTHONPATH` 绕过 |
| Python 版本不匹配 | 版本来源、`UV_PYTHON`、虚拟环境基础解释器、兼容范围 | 修复所选解释器；重建已有环境前确认授权 |
| 依赖无法共同解析 | 全成员 Python 范围、版本约束、平台标记和源 | 调整兼容约束；无法共享时讨论拆分独立项目 |
| 测试未发现或找不到工具 | 目标包的依赖组、测试路径及实际运行范围 | 修正声明或命令，不用零测试成功冒充验证 |

## 验收

明确执行目录、包名和实际命令，检查锁文件与用户变更差异。验证目标成员的安装、导入和相关真实测试；多平台原生依赖、网络、模型或数据库不足时报告实际阻塞。锁文件只读不代表环境和缓存只读，不应将二者混为一谈。

参考：[uv Python 版本](https://docs.astral.sh/uv/concepts/python-versions/)、[uv 项目环境](https://docs.astral.sh/uv/concepts/projects/config/)。
